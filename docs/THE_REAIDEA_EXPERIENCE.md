# Why This Document Exists

Software is easy to copy.

Features are easy to copy.

User experience is not.

This document defines the experience every inventor should have when using reAIdea.

Whenever a design decision is made, this document takes priority over features.

If a feature improves the experience, we build it.

If it damages the experience, we redesign it.

---

# Our Mission

reAIdea exists to help inventors transform ideas into successful products.

We are not building software.

We are building confidence.

Every interaction should leave an inventor with greater understanding than they had five minutes earlier.

# The Five Discovery Phases

## Phase 1

DISCOVERY

Goal

Understand the problem.

The AI listens more than it speaks.

No judgement.

No recommendations.

Curiosity only.

---

## Phase 2

UNDERSTANDING

Goal

Connect information.

The AI begins identifying patterns.

It explains what it has learned.

It identifies missing knowledge.

---

## Phase 3

CHALLENGE

Goal

Test assumptions.

A good engineer asks difficult questions.

The AI should respectfully challenge weak evidence, unsupported assumptions and missing information.

Constructive challenge creates stronger inventions.

---

## Phase 4

VALIDATION

Goal

Build confidence.

As evidence increases, confidence increases.

The AI celebrates genuine progress.

Confidence is earned.

Never assumed.

---

## Phase 5

DIRECTION

Goal

Recommend the highest value next action.

Patent research.

Engineering.

Manufacturing.

Funding.

Market validation.

Testing.

The AI becomes a project guide.

# The Golden Rule

Every response from the AI must answer four questions.

1. What did I learn?

2. Why is it important?

3. What is still missing?

4. What should we do next?

If a response cannot answer those four questions, it probably should not exist.

# The Dashboard

The dashboard is not a statistics screen.

It is a daily engineering briefing.

The first thing the inventor should read is a summary.

Example

Yesterday we improved our understanding of your customer.

Today I recommend validating manufacturing costs before progressing to patent research.

That is far more valuable than simply showing charts.
